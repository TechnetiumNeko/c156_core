## 内容与历史

**H01 文档身份**：工作区、分支与 object_id 决定文档范围。重命名和移动不改变文档身份。P1 沿用现有作品访问根，项目快照与作品根重构留到 P2。

**H02 不可变修订**：正文以追加修订保存，已有修订正文、作者来源与时间不可改写或删除。来源直接保存在正文修订表；旧来源未知时明确显示未知，不推测作者。

**H03 操作者**：操作者是执行保存/恢复的账号，不等于全文作者。保存稳定账号 ID，历史展示当前显示名；匿名活动以后通过服务端展示策略处理。

**H04 历史上下文**：历史读取只接受请求分支当前修订父链中可达的版本，恢复来源不得跨对象或工作区。分页固定开始翻看时的 head，继续保存不改变已经开始的翻页链；每页仍使用当前授权。游标只用于定位，不是权限凭证，跨对象/分支或不可达游标拒绝。

**H05 历史权限**：普通 read 只读当前正文。新增独立 `history_read` 动作，editor 默认具备，reader 可单独获授或撤销，沿用现有继承、私密、祖先可读和管理角色规则。获权后可以读获权前历史。

**H06 当前策略**：所有历史跟随当前文档权限；移动不保留旧目录的额外历史限制，对象自身 ACL/private 不清除。成员移除或撤销 read 后不再提供新的服务器内容访问。

**H07 已删除内容**：直接软删除或祖先目录已删除的文档，仅当前工作区 admin/owner 可列举和读取其历史；必须仍属于请求 scope。站点管理员身份不自动授予工作区权限。历史专用保留条目检查不放宽活动内容读写。P1 不提供恢复删除。

## 保存、恢复和回执

**W01 并发保护**：首次保存/恢复必须携带当前预期 revision；先比较版本，再判断正文相同。旧基础即使提交的正文恰好与新稿相同，也返回冲突。

**W02 恢复**：将选定旧修订的完整正文保存为当前正文。若当前 R3、来源 R1、正文不同，追加 R4；R4 的 parent 为 R3，restored_from 为 R1。文件名、位置、排序、metadata、权限不回退；R1–R3 全部保留。

**W03 恢复授权**：首次恢复需来源历史可读、当前 edit、冻结允许。正文相同则不追加修订、不修改原来源，仍产生可确认的无变化操作结果。

**W04 请求固定**：每次网页保存/恢复使用一个操作 ID。作用域、操作类型、基础 revision、正文或恢复来源构成固定请求。同账号同键不同业务请求拒绝；不同账号同键隔离。继续输入的新文字不是对旧请求的修改。

**W05 原子成功**：正文修订、当前指针与成功回执在同一事务提交。失败全部回滚；无变化操作也有回执。成功回执默认保留，不在 P1 自动过期或 GC，不重复存全文。

**W06 授权与重放**：先检查身份和当前资源 read，再查本人回执。已有同请求成功回执仅返回无正文结果，不再次执行编辑；此时即使后来失去 edit 或冻结，也可确认既有结果。首次操作才检查 edit/冻结/基础，首次恢复额外检查 history_read。失去 read 不得查询或重放结果。已删除资源仍按 H07 处理。

**W07 结果和当前稿分开**：回执证明该操作得到哪个 result_revision，不代表文档当前仍是它。响应包括独立当前 revision 标识；不将旧回执包装成旧全文 Document。读取旧正文必须走历史鉴权。

**W08 不确定结果**：网络、响应丢失或解析失败后保留固定 pending。查询暂不存在不证明未执行，继续查询或同键同请求重试，不自动换键。确定的领域失败与不确定传输失败分开显示。

**W09 客户端推进**：保存期间可继续输入。确认结果后仅确认固定请求保存的正文，保留较晚输入。若服务器 head 已前进，保留本地稿并进入比较/冲突，不能把旧成功当成最新稿。已有 pending 未处理前不建立另一保存/恢复操作。

**W10 恢复前草稿**：未保存稿先由用户保存、明确放弃或取消。保存冲突、在途保存和待确认先处理。保存当前稿后重新读取当前版本与恢复比较，再确认恢复。预览过期返回冲突，不自动换基础重试。

## 本地草稿与页面

**L01 最小范围**：原生 IndexedDB；每个账号/工作区/分支/对象一份当前草稿，包含格式版本、基础修订、正文、本地代际和固定 pending；无草稿列表、无多副本、无自动封存恢复前副本。

**L02 首次发送前持久化**：先等待固定 pending 与草稿的本地事务完成，再发送网页保存/恢复。写入失败不显示已存本机，不发出这次新操作；保留内存和复制出口。已发送旧 pending 可按同键查询/重试，但不能改写它。

**L03 找回**：同账号重新打开时检查服务器资源，发现草稿后提示继续或明确丢弃。不自动载入、不自动保存。基础过期比较服务器当前正文和本地文字。待确认 pending 优先核对。

**L04 账号与退出**：退出前排空或确认关联本地写入，主动退出隐藏文档、释放资格并保留已存稿；不再要求为退出而放弃草稿。其他账号不展示、不写入或清理原账号记录。会话失效暂停服务器写入、保留内容。

**L05 无服务器权限稿**：当前已认证的原账号在文档删除或失去对象访问时，可以在本机稿出口复制/删除其缓存文字，不能经此读取服务器正文、历史或保存。未认证及不同账号不加载此出口；原账号的已显示内存稿可以在会话暂停时复制。

**L06 单编辑页**：同浏览器同草稿键仅一页取得编辑资格，其余只读；不同文档可分别编辑。这不是服务端冻结或跨设备锁，跨设备仍靠 W01。后续实时协作再修改本条。

**L07 防旧写复活**：使用 Web Locks 协调资格；每次接管在 IndexedDB 事务内更新持久 fencing token，所有写入、确认和清理核验 token。清空正文保留空记录，并使清空前捕获的写入 token/代际失效，不删除防护代际。当前持锁页清空也须防同页旧定时器复活，不能只在另一页接管时更新 token。旧定时器、账号回调或释放后的写入不得重建旧稿。

**L08 存储故障**：本机已存只在事务完成后显示。浏览器配额、关闭/崩溃可能导致最后尚未落盘字符无法找回；错误明确呈现。默认不支持所需跨页协调能力时只读，不自行增加租约系统。

**L09 历史界面**：历史与当前编辑 buffer 分离，查看/比较不会替换未保存稿；首版只读行级差异。管理员有可发现的已删除文档入口，不要求预先知道 object_id。

## 数据库管理

**M01 单一 schema 来源**：Alembic 管迁移，新建/现有库接管/旧容器导入统一迁移链；初始化和导入模块保留业务数据与生命周期职责。SQLAlchemy 仅迁移使用，运行时 sqlite3/Repository/UoW 保持。

**M02 单一版本依据**：接管后以 Alembic revision 检查版本。旧 user_version 只识别基线或阻断旧应用；升级后使用非 2 的兼容标记，使旧应用拒绝写入，不再独立递增协议号。

**M03 接管核验**：只有真实结构与固定协议 2 基线一致且数据完整才登记基线：核对列、外键、CHECK、部分索引、不可变触发器，不仅比较 user_version。缺损/未知库拒绝 stamp，不 stamp head 跳过迁移。

**M04 维护与事务**：停止所有写入口，源版本可读的 SQLite backup API 备份，显式升级、核对、再启动。DDL/数据/Alembic revision/兼容阻断处于真实事务中；外键设置在 BEGIN 前安排，批量重建保留约束和触发器，提交前 foreign_key_check。启动不隐式迁移。

**M05 故障恢复**：迁移失败回滚并保持维护状态。尚未重新开放写入时可显式恢复备份；已经产生新稿后修复前进，不静默覆盖为旧备份。测试库可以重建、做破坏性实验；原始来源样本与未授权文件不因初始化失败被删除。

## HTTP/服务契约

以下名字固定给实施计划使用，接口 JSON 明确投影，不暴露数据库记录：

| 操作 | HTTP | 服务方法 |
| --- | --- | --- |
| 活动文档历史 | `GET /api/document/history`，object_id、可选 cursor/limit | `ContentService.list_document_revisions` |
| 修订正文 | `GET /api/document/revision`，object_id、revision_id | `ContentService.read_document_revision` |
| 两版差异 | `GET /api/document/diff`，object_id、from_revision_id、to_revision_id | `ContentService.compare_document_revisions` |
| 已删除列表 | `GET /api/documents/deleted`，可选 cursor/limit | `ContentService.list_deleted_documents` |
| 带回执保存 | `PUT /api/document` 增加 operation_id | `ContentService.save_document_operation` |
| 恢复 | `POST /api/document/restore`，object_id、source_revision_id、expected_revision_id、operation_id | `ContentService.restore_document_revision` |
| 结果查询 | `GET /api/document/operation`，object_id、operation_id | `ContentService.get_operation_status` |

写入返回 `{operation: {operation_id, operation_type, result_revision_id, changed, created_at}, current_revision_id}`；查询成功同形，暂不存在返回 `{operation: null}`。回执不含正文、历史 metadata 或其他操作的身份。错误沿用现有统一领域错误 JSON；写入继续 CSRF 校验、严格请求字段验证。

现有 CLI 和旧本地 Web 可继续调用无回执保存契约，仍使用相同内容服务并记录真实操作者，不绕过权限或并发检查。Vue 的新保存使用固定 operation_id；首版不新增 CLI 历史命令。

已认证 Bootstrap 追加 `scope: {workspace_id, branch_id}`，供完整草稿键使用；匿名 nonce 响应不追加 scope，不为无权访问根的账号额外投影 root_id。它是现有应用 scope 的投影，不是新工作区创建/切换能力。

历史列表返回 `{revisions: [...], head_revision_id, next_cursor}`；修订返回仅修订信息及 content；差异返回两端 ID 与 unified diff 文本；已删除列表返回 `{documents: [...], next_cursor}`，只投影 scope 内的当前保留名称/路径，不声称它们是历史树。
