# 本地草稿

[索引](README.md)，[行为规范 L01–L08](行为规范.md)，[保存确认](04-保存确认.md)

原生 IndexedDB 每个账号、Bootstrap 工作区、分支、对象只保留一份当前草稿。记录包含格式版本、正文、基础 revision、本地代际、fencing token 和固定 pending；不含会话秘密，不提供草稿库存列表、多副本或自动封存。

DocumentSession.open 先确认当前账号和 scope，再检查服务器文档，然后读本机记录。找到草稿先提示继续或明确丢弃，不自动载入或保存；基础过期保留原基础并进入比较。pending 优先确认。明确采用最新正文手动合并后，startMerge 同步持久化新基础，合并前正文继续保留在只读参考区；未明确采用前不推进基础。这份合并前参考只在当前页面内存中，保存编辑稿也不会自动移除。切换文档、退出、接受其他账号、再次开始合并或清理当前稿之前，须先合并或复制需要的文字，并通过“移除合并前参考”明确处置，也可取消并留在页面。处置仅移除参考，不删除已存的当前稿；普通已存稿可以直接离开。

主动退出通过 SessionState 生命周期 hook 排空本机写入，再隐藏内容、释放 Web Lock，保留已存稿。会话失效暂停服务器写入，已显示内存稿可复制。协调器独立保留原账号归属；失效恢复直接返回其他账号、或先暂停为匿名再恢复为其他账号，均先排空写入、停止旧回调、隐藏原内容并释放资格，再接受新账号。若本机写入或参考处置未完成，保留原内存并阻止接受其他账号。本机写入失败默认停留、复制或重试；只有用户明确确认未落盘文字可能丢失，才可强制 leave 后重试退出，不能显示为已保存。该确认不代替合并参考的独立处置。

无服务器权限或文档删除时，当前已认证原账号可复制/删除这一篇缓存。草稿区不依赖 server document 或 root 渲染。目录下“找回无法打开文档的本机稿”通过已知文档标识检查单篇记录；没有缓存自动枚举。删除当前文档会保留本机稿并尝试打开其本机出口；尚有未处置的合并参考时，保留当前页面，处置参考后才能切换。其他账号及未认证页面不新加载原账号记录。

本机出口删除 pending 须明确告知：这不会取消或撤销已经发出的保存/恢复，请求可能已提交或稍后完成，也可能失去确认数据。可访问文档的 pending 仍须先核对。

Web Locks 持有整个编辑生命周期；IndexedDB 每次接管及清空推进 fencing，空记录仍保留 token，旧回调不能复活文字。无能力或未取得编辑资格时只读。不实现心跳租约。

`frontend/tests/document-session.test.ts` 使用真实协调器和生产 DraftStore 配合 fake-indexeddb 检查事务、fencing、失败保稿、账号隔离和手动合并重开。它不能证明浏览器真实配额、崩溃/断电持久性或跨页故障；本轮未做原生浏览器实验与截图。

界面使用 DocumentSession.canEdit 投影现有编辑守卫：有效身份与本地资格、可访问文档、未离开/清理、没有待选择的找回稿。主动保存期间继续输入可用；重开后尚未处理的 pending 保持只读。它不推断服务器权限，App 同时使用服务返回的 edit action。
