# 本地草稿

[返回索引](README.md)，[查看决策](决策记录.md)

状态：最小交付范围和原生 IndexedDB 已确认，生命周期待细化。按 [D20](决策记录.md)，P1 提供刷新后找回未保存正文，不交付草稿列表、多副本或复杂管理。

恢复旧正文前先要求用户处理未保存稿，已按 [D19](决策记录.md) 确认；不增加自动封存恢复前草稿的副本管理。存储选择按 D21 执行。

## 现状

[EditorState](../../frontend/src/state/editor.ts) 的草稿目前在内存；[CodeMirror 编辑器](../../frontend/src/components/MarkdownEditor.vue) 管理当前正文与本地撤销。已有身份暂停、冲突保稿和请求代际应继续复用。

## 已确认的存储与边界

按 [D21](决策记录.md)，用浏览器原生 IndexedDB 保存草稿，封装一个小型存储模块，键至少包含账号、工作区、分支和对象。记录基础 revision、草稿正文、本地代际、更新时间，以及[保存确认](04-保存确认.md)所需的操作标识和发送内容。不存会话秘密。具体字段与写入策略在规格中细化。

| 候选存储 | 收益 | 取舍 |
| --- | --- | --- |
| 浏览器原生 IndexedDB | 异步事务，适合存正文和版本信息，可处理单记录条件写入 | 需封装少量打开、读写和错误处理代码 |
| localStorage | 接口简单，适合少量字符串数据 | 读写同步；多标签页的读改写缺少数据库事务，需要额外防覆盖策略 |

参考：[IndexedDB API](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)、[Web Storage API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API)。以上为选型比较，已选择原生 IndexedDB，不引入新的持久化框架。

正文输入可以合并频繁的本地写入，但页面不能把“定时器还没落盘”显示为已存本地。浏览器配额或存储失败时给出明确状态及复制/导出出口。

找到草稿后重新获取服务器正文并鉴权：基础未变可以继续编辑；基础变了展示当前稿和本地稿，进入明确的比较处理。不能自动绑定最新 revision 后覆盖保存。

## 已确认的主动退出行为

按 [D22](决策记录.md)，主动退出时保留该账号的草稿记录，退出后停止展示，其他账号不加载它；同一账号再次登录、通过文档访问检查并打开对应文档时，再提供找回。它继续使用同一条草稿记录，不额外建立封存副本或管理列表。

主动退出与会话意外失效的行为需要区分，不能把会话失效直接解释为用户同意丢稿。账号切换时重新绑定草稿作用域，旧账号的在途回调不得写入或删除新账号的记录。

## 已确认的同文档多标签页行为

按 [D23](决策记录.md)，P1 在同一浏览器存储范围内，对“同账号＋工作区＋分支＋文档”仅允许一个标签页编辑和维护草稿，其他标签页只读；原编辑页释放资格后，另一页重新获取资格并读取最新服务器状态与草稿。不同文档可以分别编辑；不同设备/浏览器的服务端保存仍由 revision 并发检查保护。

候选技术方案是原生 Web Locks 协调本地编辑资格，IndexedDB 事务保护记录更新；BroadcastChannel 可通知资格变化，但通知本身不充当互斥锁。API 可用性、关闭/刷新释放、在途写入与接管顺序在规格中细化。[Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)、[Broadcast Channel API](https://developer.mozilla.org/en-US/docs/Web/API/Broadcast_Channel_API)

这是实时协作接入前的阶段规则，不在 P1 预先实现多标签页共享编辑或自动合并。后续接入实时协作时再调整该产品行为。本地编辑资格不等同于服务端权限或文档冻结，不能代替服务端 revision 并发检查。

## 已确认的刷新找回行为

按 [D24](决策记录.md)，重新打开文档时先取得服务器当前正文并鉴权，发现当前账号对应的未保存稿后提示用户选择：继续本地草稿，或明确丢弃草稿并使用服务器版本。找回操作只进入编辑器，不自动保存至服务器。

如果草稿基础 revision 与服务器当前 revision 不同，进入当前正文与本地稿的比较处理，保留原基础和正文，不自动换成新基础后重发。保存结果待确认的草稿先按[保存确认](04-保存确认.md)核对操作结果，不能因重新加载而忽略不确定状态。

基础 revision 未变时也先提示选择，不自动载入。两种选择均不得将尚未提交的本地内容显示为服务器已保存。

## 必须决定的细节

| 场景 | 选择影响 |
| --- | --- |
| 保存成功且仍有后续输入 | 只清理已确认部分，保留仍未保存的正文 |
| 无权限/文档已删除 | 不能继续服务器写入；本机稿的复制/删除/封存行为需明确 |
| 升级或未来协作接入 | 草稿格式需有版本；未来 CRDT 缓存单独迁移，不能把全文重灌当同步 |

## 验收方向

刷新后可恢复已经落盘的草稿；存储失败可观察；冲突后原基础和本地正文仍在；迟到保存响应不覆盖后续输入；不同账号、分支、对象和标签页按确认规则隔离。

验证重点是草稿存储与编辑状态的真实行为。页面默认截图查看，不自动点击按钮或填表。缓存保留、退出行为和防覆盖规则确认后再实施。
