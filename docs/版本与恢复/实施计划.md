# P0/P1 版本与恢复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `superpowers:subagent-driven-development`，依次执行以下五项任务；每项由一位 implementer 完成并接受独立 reviewer 审阅。Steps use checkbox (`- [x]`) syntax for tracking。用户已授权审阅、编写计划后连续实施，无需再次请求执行方式或微小实现确认。

**Goal:** 交付可授权读取和恢复的不可变正文历史、可查询的幂等保存结果，以及隔离账号和标签页的单份本地草稿。

**Architecture:** 沿用 `ContentService → ContentOperations / Repository → sqlite3` 和同连接 UoW；Alembic 只拥有 schema 迁移。操作回执与正文同事务，Vue 的 API、编辑状态、本地存储与编辑资格分别负责自己的边界，通过固定请求衔接。

**Tech Stack:** 既有 Python/FastAPI、sqlite3、Vue/TypeScript、CodeMirror 6；迁移依赖固定 `Alembic==1.20.0`、`SQLAlchemy==2.0.54`（已核实可安装）；本地存储使用原生 IndexedDB，编辑资格使用原生 Web Locks。

**Spec:** [行为规范](行为规范.md)是 binding spec；[P0-P1设计稿](P0-P1设计稿.md)保留架构与取舍。行为变化必须定位语义 ID 并同步规范和证据。本计划依据提交 `569915a` 的现有实现。

## Global Constraints

- P1 沿用现有作品访问根；不实现实时协作、项目快照、分支创建、恢复删除、草稿列表或多副本。
- SQLAlchemy 仅迁移使用，运行时 sqlite3/Repository/UoW 保持；Repository 不提交事务，启动不隐式迁移。
- 保留 CLI 和旧本地 Web 的无 `operation_id` 保存契约，共用内容服务、授权、操作者来源和并发检查。Vue 新保存必须带固定 `operation_id`。
- 账号＋操作 ID 唯一；成功回执不含正文，默认保留，不在 P1 自动过期或 GC。
- 已有 pending 未处理前不建立另一保存/恢复操作；继续输入的新文字不能修改固定请求。
- IndexedDB 清空草稿保留空记录及 fencing token；所有写入、确认、清理均核验 token。
- 没有所需跨页协调能力时默认只读，不增加心跳租约或替代协调依赖。
- 新版以 Alembic revision 为版本依据；旧 `user_version` 仅识别协议 2 基线及通过非 2 标记阻断旧程序。
- 每位 worker 只修改自己的文件范围；共享文件按任务顺序交接，不回退他人改动。新架构决策提交主 agent，由其向用户集中提出。
- 优先复用已有测试；新增永久测试仅覆盖关键行为和缺口，不复制算法、不用源码字符串或只断言 mock 的测试代替行为证据。
- UI 验证最多截图，不执行浏览器自动点击、填表或交互流程。不为本轮引入浏览器测试平台或重要新依赖。
- 文案使用自然中文，不使用“xxx · xxx”拼接；文档能力状态必须对应实际行为与检查，不把计划当成已完成能力。

## Review Focus

1. caller 已开启 SQLite 事务再调用 `create_schema`：初始化业务数据失败应把 DDL、版本和数据一起回滚，SQLAlchemy 接管/关闭不得隐式提交或回滚。由任务 1 的 caller-rollback 用例钉住。
2. 协议号为 2 但缺 CHECK、部分索引或不可变触发器：拒绝 stamp；升级失败保持旧结构与旧版本，新版本的兼容标记必须阻断旧应用。由任务 1 的损坏基线与失败注入用例钉住。
3. 旧成功回执遇到冻结、撤销 edit、服务器已产生新 head：有当前 read 才可确认，只返回结果和独立 head，不返回旧正文、不重新执行。由任务 3 的权限改变及旧回执测试钉住。
4. 保存期间输入、退出或接管后迟到的请求与本地写入：固定 pending 不变，较晚文字保留，旧 token 不能重新创建已清空草稿；退出不要求放弃已存稿。由任务 4 的状态与代际行为测试钉住。
5. 祖先目录已删或对象移出私密目录：历史使用当前策略，已删除入口仅工作区 admin/owner 可发现，活动读写仍拒绝已删除对象。由任务 2 的保留条目及移动测试和任务 5 的入口接线审阅钉住。

### Task 4: IndexedDB、Web Locks 与编辑/账号状态

**Files / ownership:** 可为真实 IndexedDB 模块行为验证新增 devDependency `fake-indexeddb@6.2.5` 并更新 `frontend/package.json`/lock；不增加生产框架或大型测试辅助层。新增 `frontend/src/drafts/store.ts`、`frontend/src/drafts/lease.ts`、`frontend/src/drafts/types.ts`、`frontend/src/state/document-session.ts`。修改 `frontend/src/state/editor.ts`、`frontend/src/state/session.ts`；扩展 `frontend/tests/editor.test.ts`、`frontend/tests/session.test.ts`，新增 `frontend/tests/document-session.test.ts`。仅补充必要生命周期回调，不在本任务重写 Vue 布局。

**Interfaces:**

- `DraftKey = {userId,workspaceId,branchId,objectId}`；无模糊字符串拼接，使用稳定编码。`DraftRecord = {formatVersion:1,key,fencingToken:number,generation:number,baseRevisionId:string|null,content:string|null,pending:PendingOperation|null}`；`content:null` 为保留 fencing 的空记录。
- `PendingOperation` 是只读判别联合：`{kind:'save',request:SaveDocumentOperation}` 或 `{kind:'restore',request:RestoreDocumentOperation}`；存储 request 本体，不只摘要。本地 draft/generation 可继续更新但不得改变 pending。
- `DraftStore.claim(key):Promise<DraftRecord>` 在 IndexedDB readwrite 事务递增 token；`.read(key):Promise<DraftRecord|null>`；`.write(record,expectedToken):Promise<void>`；`.clear(key,expectedToken):Promise<DraftRecord>` 写入空记录并递增 token，使清空前捕获的旧写入失效；返回新 fencing record 给当前持锁协调器；`.flush():Promise<void>` 等待本实例关联事务完成。失配抛出可识别的 stale fence 错误，不能 upsert 复活。
- `acquireDraftLease(key):Promise<DraftLease|null>` 使用 `navigator.locks.request` 持有完整键排它资格；`DraftLease` 提供 `release():Promise<void>`。无 Web Locks、未取得资格或无法可靠存储时不建立新操作；BroadcastChannel 仅可通知，不能授予资格。
- `DocumentSession` 组合 `ApiClient,EditorState,DraftStore`，统一提供 `open(scope,objectId,userId):Promise<void>`、`edit(text):void`、`continueDraft():Promise<void>`、`discardDraft():Promise<void>`、`save():Promise<void>`、`restore(sourceRevisionId,expectedRevisionId):Promise<void>`、`reconcilePending():Promise<void>`、`retryPending():Promise<void>`、`flush():Promise<void>`、`leave(options?:{acknowledgeUnstoredLoss?:boolean}):Promise<void>`（默认 false；仅在用户确认未落盘文字可能丢失后使用 true）。对 UI 暴露 `localStatus`、`recovery`、`leaseHeld`、`localOnlyContent`；详细联合类型随实现一并交付。
- `SessionState` 接受生命周期 hook `beforeLeaveIdentity():Promise<void>`，退出先 drain/确认失败，再隐藏文档、释放资格；会话失效与主动退出分别处理，前者允许已显示内存稿复制，后者隐藏原账号内容。

- [x] **1. 实现单份原生存储与资格。** 每个完整键一条；claim、write、clear 在事务内检查/更新 fencing，完成事件后才 resolve，不用单条 request success 冒充事务完成。release 前 flush 或阻止排队写入；写、清理和确认都捕获 token。清空不 delete objectStore 记录，并旋转 token/代际阻断同页清空前的 debounce；写入闭包捕获当时 token，不在迟到回调中读取新的可变 token。存入 IDB 的 record/request 必须投影为纯数据，避免 Vue proxy 的 DataCloneError；旧定时器、旧账号回调和旧 token 不能改写新页。无支持时只读并给明确原因。

- [x] **3. 实现找回、退出和无权限出口。** open 先核实当前账号与服务器资源，再展示继续/丢弃提示，不能自动覆盖编辑器或保存；pending 优先核对。原账号认证且资源无访问或删除时只读取该键的本地稿供复制/清理，不调用历史或保存。主动退出 drain 后保留已存稿、隐藏文档并释放锁；存储失败可确认继续退出但不能谎称落盘。其他账号不读写清理原记录；会话失效暂停服务器操作并保留已显示内存稿。
