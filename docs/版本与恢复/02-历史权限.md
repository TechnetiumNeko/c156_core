# 历史权限

[返回索引](README.md)，[查看决策](决策记录.md)

状态：P1 主要产品规则已确认，待服务契约与实现细化。不能根据知道 revision_id 就返回正文。

## 已确认的行为

[D03](决策记录.md)：普通阅读权限只开放当前正文，查看正文历史需要额外资格。历史列表、详情和比较不能仅凭普通 read 放行。

[D04](决策记录.md)：获得某文档的历史查看资格后，可以查看该文档获权前的历史，不按获权时间截断。资格必须当前有效，并受文档、工作区及分支访问范围约束，不因此开放其他对象或私密分支。

[D05](决策记录.md)：历史查看是独立权限，编辑角色默认拥有，可单独授予或撤销。可以向不能编辑的审阅者授予历史资格；编辑资格与历史资格分别判定，不能把获准 edit 自动当作获准查看历史。

[D06](决策记录.md)：恢复旧稿要求同时具备来源历史的查看资格和当前文档编辑权限，并遵守冻结规则；P1 不另设独立恢复权限。

[D07](决策记录.md)：文档全部历史跟随当前访问限制及独立历史查看权限。文档移出私密目录后，有效具备历史资格的人可以查看包括私密时期在内的旧稿；移入私密目录后，全部历史受新的访问限制。普通读者仍只读当前正文。对象自身的私密设置与 ACL 不因移动自动清除。

不按旧目录或当时权限对正文历史另设限制。权限变更的审计记录仍有独立用途，不能将正文恢复当作恢复旧授权。

[D08](决策记录.md)：P1 已删除文档的历史仅向该工作区当前 admin/owner 开放，普通编辑者及仅持历史查看资格者不能读取；正文与修订继续保留。站点管理员身份本身不授予其他工作区内容访问权。

[D09](决策记录.md)：P1 不提供原位恢复删除。管理员可以查看、复制已删除正文；恢复删除留到后续。P1 的恢复旧稿作用于现存活动文档。

[D10](决策记录.md)：普通共同写作中，获准查看某修订的人可以看到操作者显示名。操作者指执行保存或恢复的人，不表示整篇正文作者；旧记录无法确认时显示未知。未来匿名活动按专门的展示规则隐藏身份，不能将普通历史响应直接用于匿名场景。

未来显式发布的固定版本由发布规则定义，不等于开放全部编辑历史。

## 已有基础

[AccessPolicy](../../src/access/policy.py) 已处理成员角色、目录继承、祖先可读、私密和冻结。[应用事务](../../src/services/unit_of_work.py) 在一次操作中解析会话及当前策略。

当前 revision 记录包含工作区和对象，未记录分支来源。P1 尚无分支创建，但历史查询的上下文需要与后续分支隔离兼容。

## 推荐方向

历史读取使用当前身份和当前授权。曾经拥有权限不等于现在仍可访问；当前可以阅读最新正文，也不直接决定可以查看全部旧稿。历史列表、详情、比较、恢复分别检查资格。

活动文档的历史读取按独立历史资格检查，编辑角色的默认资格与单独授权/撤销见 D05。恢复所需的权限组合按 D06 执行。已删除文档的历史入口按 D08 限该工作区当前管理员访问。

管理员的当前管理资格也不能用来绕过其他人的文档冻结。每次历史请求和恢复操作均检查当前资格；移出成员、撤销历史资格或失去文档访问权后，旧凭据和已知修订 ID 不继续授予读取权。保存结果查询同样不能绕过当前授权；本机已保存内容的封存/清理行为见[本地草稿](05-本地草稿.md)。

## 后续规格细化

主要产品规则以 D03–D10 为准。后续落实独立历史能力在现有角色与 ACL 中的映射、历史上下文可达性、已删除对象的查询入口，以及身份信息的服务端展示字段。已确认不按获权时间划分历史；访问限制必须由服务端执行，不能只在 UI 隐藏按钮。

匿名活动的具体规则留到该子系统设计，不要求 P1 实现匿名活动。操作者显示名是否取当前资料或保存时值，在[修订与恢复](03-修订与恢复.md)的数据方案中细化。

## 验收方向

列表、内容、差异和错误信息均不泄露无权访问的历史；撤权立即作用于新的请求；恢复不会改变成员、ACL 或冻结。具体规则进入[修订与恢复](03-修订与恢复.md)及[保存确认](04-保存确认.md)的服务契约。
