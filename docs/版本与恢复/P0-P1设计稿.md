# P0 / P1 设计稿

[目录索引](README.md)，[已确认决策](决策记录.md)

状态：**整体方案已接受，五项任务与整分支审阅及修复复审已通过，阶段性发布中**。D01–D25 及整体默认项已获连续实施授权。行为语义的权威入口是[行为规范](行为规范.md)；本文保留架构与取舍背景。

目标：保存过的正文可追溯；旧页面不能覆盖新稿；旧正文可恢复；网络响应丢失可查证；刷新可找回本机未保存稿。

## 1. 范围和整体边界

| 部分 | 本轮交付 |
| --- | --- |
| 数据库管理 | 标准 Alembic，唯一迁移版本依据，新建/接管/导入使用同一 schema 来源 |
| 正文版本 | 不可变修订、操作者和来源、历史列表/读取/比较、恢复旧正文 |
| 权限 | 独立历史查看能力，沿用当前目录、ACL、私密和冻结规则 |
| 保存确认 | 同键幂等重试、持久化结果、只读查询，与正文变更同事务 |
| 本地草稿 | 原生 IndexedDB、单份刷新找回、账号隔离、同文档单标签页编辑 |
| 网页 | 历史面板、差异预览、恢复确认、草稿找回与保存状态 |

项目快照、分支创建、实时协作、原位恢复删除、草稿列表和多副本不在本轮。历史服务供所有入口复用，本轮新增操作先交付 Vue 网页。

默认继续使用现有工作区/分支/文档 scope，P1 不提前增加作品根字段；作品根和完整树快照到 P2 一起设计。

## 2. 模块职责

- `ContentService` 提供历史读取、保存和恢复用例，拥有授权与应用事务。
- 事务内内容操作负责来源归属、修订可达性、并发检查和指针变化；Repository 执行 SQL，不自行提交。
- 操作结果由独立 Repository 存取，参加同一个 UoW，不新增单独的数据库或服务部署。
- Alembic 环境负责 schema 及结构性数据迁移；管理入口负责维护流程、备份、初始化业务数据、旧数据导入与验证。
- 前端把编辑状态、草稿存储、标签页编辑资格和 API 客户端分开。Vue 组件展示结果，不定义权限算法。

默认 SQLAlchemy 只用于 Alembic 迁移环境，运行时继续现有 sqlite3/Repository/UoW。这是本稿建议的依赖边界，不包含运行时 ORM 重构。

## 3. 数据模型建议

### 正文修订

在 `document_revisions` 直接扩展来源字段，保留现有不可变约束：

| 信息 | 语义 |
| --- | --- |
| `actor_id` | 执行保存或恢复的账号；旧数据无法确定时为空 |
| `source_kind` | 普通保存、恢复、导入等来源；旧来源不明时明确标记未知 |
| `restored_from_revision_id` | 恢复时指定的源修订，必须属于同一工作区与对象 |
| `parent_revision_id` | 新修订产生前的当前修订，继续形成不可变正文链 |

默认保存稳定账号 ID，展示时读取当前显示名；不额外保存昵称快照。操作者不等于全文作者，未来匿名展示在服务端投影时隐藏。旧记录不按当前所有者猜测作者。

修订属于工作区与对象；P1 的历史读取沿请求分支的当前 revision 父链验证可达性，不开放同对象所有修订的无范围枚举。分支创建前保留该约束，防止以后串读其他分支。

### 操作确认记录

建议新增精简的成功操作记录，字段包括：账号、操作 ID、工作区/分支/文档、操作类型、请求摘要、结果 revision、是否改变正文、提交时间。

`账号＋操作 ID` 唯一。请求摘要覆盖完整业务请求，包括作用域、操作类型、基础 revision、正文或恢复来源；JSON 字段顺序不影响摘要，正文字符不做额外语义归一化。

该记录与正文修订用途不同：无变化操作没有新修订，但仍需要确认结果。记录不重复存整篇正文。默认本阶段保留成功回执、不做自动过期或回执 GC；以后引入过期策略时，再定义迟到重试的拒绝规则。

## 4. 授权和接口契约

历史查看能力作为现有动作体系的扩展，默认给 editor，沿用现有管理角色边界；支持单独授予与撤销，遵守目录继承、祖先可读和对象私密限制。

| 用例 | 检查和结果 |
| --- | --- |
| 历史列表/详情/比较 | 当前文档可读 + 历史查看资格 + 所选修订在分支历史中可达 |
| 恢复活动文档 | 来源历史可读 + 当前文档可编辑 + 冻结允许 + 预期 revision 匹配 |
| 已删除文档历史 | 当前工作区 admin/owner；包括因祖先目录删除而不可见的文档，不允许复活目录 |
| 查询操作结果 | 当前调用者拥有该操作，且仍可访问对应资源；不返回其他人的结果或旧正文 |

所有正文历史跟随当前授权。移出私密目录不会额外保留私密时期限制；对象自己的 private/ACL 不因移动清除。服务器每次请求重新检查权限，已知 revision 或操作 ID 不能绕过鉴权。

服务接口至少覆盖：分页历史、指定修订、两版比较、带操作 ID 的保存/恢复、操作结果查询。具体 URL 和字段统一在实施规格中定义，不各入口自行拼接 SQL。

默认历史按父链从当前向前分页，游标绑定对象、分支和读取时的历史 head；后续保存不扰乱已开始翻看的列表。差异首版用只读行级比较，不增加自动三方合并。

## 5. 保存与确认流程

1. 浏览器生成操作 ID，固定本次请求，并将待确认请求与草稿信息可靠写入 IndexedDB。
2. 服务端在短写事务中鉴权、查找相同操作；已有成功结果且请求相同则返回回执，同键不同请求拒绝。
3. 首次操作检查基础 revision，再追加正文修订、更新指针并写成功回执。正文无变化则只写无变化回执，仍先做版本检查。
4. 提交成功后才响应。事务失败同时回滚正文和回执。
5. 响应丢失时显示结果待确认，查询或重试保持原操作 ID 和原请求；查询暂时不存在不能直接断言失败。
6. 确认后区分结果修订与服务器当前修订。若随后已有其他修改，不能把旧成功回执当作最新正文。

保存期间可以继续输入，后续文字属于下一次操作。收到旧操作的成功响应时，只确认它实际保存的正文；更晚输入继续保留为草稿，不整条删除缓存。账号、对象、请求代际不匹配的迟到响应不应用。

操作查询和重复回执默认返回状态、结果 revision、是否无变化及时间，不附历史正文。需要读正文时走相应内容授权；独立历史权限不会被结果查询绕过。

## 6. 恢复流程

历史面板是只读视图，与当前编辑器分开。选择旧稿后展示其与当前已保存正文的差异，再确认恢复。

当前有未保存稿时，先保存、明确放弃或取消。存在在途保存、冲突或待确认结果时先处理。保存当前稿以后重新生成恢复比较及预期 revision。

恢复正文不同：追加 R4，正文来自 R1，父修订为恢复前 R3，恢复来源为 R1；R1–R3 全保留。恢复正文相同：返回无变化回执。文件名、位置、排序、metadata、权限都保持当前状态。

预览后服务器内容变了，恢复返回冲突并重新比较；不替用户换成最新 revision 再恢复。结果丢失复用上一节的查询/重试机制。

## 7. 最小草稿生命周期

- 每个账号/工作区/分支/文档保留一份当前草稿及基础 revision、格式版本、本地代际和待确认操作。界面没有草稿列表。
- 合并频繁写入，只有 IndexedDB 事务完成才显示本机已保存；存储失败可观察，保留内存内容和复制出口。不能保证浏览器被强制终止前每个最后输入字符都已写入。
- 主动退出保留已存草稿；退出后不展示给其他账号。会话失效暂停服务器写入，保留稿件。
- 同账号重新打开并通过资源检查后，提示继续草稿或明确丢弃。基础过期则比较当前正文与本地稿，禁止自动覆盖服务器。
- 有待确认操作时先核对结果，再决定是否属于未保存草稿；不将已提交请求当成另一份新操作重发。
- 默认文档删除或失去服务器访问权时，本机稿仍保留给原账号，提供明确的本机文本复制/删除出口，不发起服务器读取或保存，也不借缓存开放历史接口。

最后一条是默认异常处理建议，不是新的服务器访问授权；浏览器中已取得的文字本就无法通过服务器撤权收回。

## 8. 标签页协调的技术建议

默认使用原生 Web Locks 为完整草稿键取得编辑资格，IndexedDB 事务及本地代际保护读写/清理；BroadcastChannel 只通知状态。只有持有资格的页可以编辑、保存、恢复和更新草稿。

正常释放前完成或停止关联写入；接管时重新读取服务器状态和草稿；旧页的异步写入不能覆盖接管后的代际。页面恢复、身份切换和锁丢失都检查资格。

暂不构建自定义心跳租约系统。不支持所需跨页协调能力的浏览器，默认只读并说明原因；该取舍已接受并实现。后续实时协作替换这条阶段限制。

## 9. 迁移与部署

基线迁移固定描述当前 schema，后续迁移增加历史能力、修订来源和操作确认。新库从迁移链建立；当前测试库可重建，也提供经过核验的协议 2 基线接管路径。历史迁移不导入不断变化的最新建表函数。

默认维护窗口直接停止服务和其他写入入口，在同一部署互斥范围内完成备份、显式 Alembic upgrade、核对和新服务启动。旧 CLI/后台进程不得继续连接写入。启动不自动 upgrade。

采用实际 SQLite BEGIN 保护 DDL、数据和 Alembic revision 更新；需要 batch 重建时明确外键、CHECK、部分索引和不可变触发器的保留。源版本备份和新建库检查改为识别迁移 revision，不沿用新应用只认一个旧整数的备份限制。

迁移失败回滚。迁移成功但新服务启动失败，尚未开放写入时可按显式运维流程恢复备份。已产生新稿后优先修复前进，不静默恢复旧备份。默认不提供会丢失新数据的通用降级命令。

## 10. 开发顺序与验收

| 顺序 | 交付 | 核心证据 |
| --- | --- | --- |
| 1 | Alembic 和管理入口统一 | 新建库、旧库升级、失败回滚、重复运行、版本不匹配拒绝 |
| 2 | 历史能力与修订来源 | 独立授权、未知来源、父链可达性、已删除管理员查看 |
| 3 | 保存回执与结果查询 | 同键只应用一次、同键不同请求拒绝、响应丢失可确认、无变化结果 |
| 4 | 恢复服务 | 追加历史、来源一致、并发冲突、冻结、正文和回执原子回滚 |
| 5 | 本地草稿和标签页协调 | 刷新提示、账号隔离、退出保留、单编辑页、迟到响应不丢稿 |
| 6 | 网页历史与恢复闭环 | 可浏览/比较/恢复，待确认与未保存状态清晰，相关构建检查通过 |

优先复用已有测试；只给关键新行为和覆盖缺口加测试。数据库和协议证据使用真实生产逻辑；UI 默认截图查看，不自动点击或填表。

本稿不承诺精确并发人数、自动冲突合并或实时同步。完成这一轮后再进入 P2 项目快照。

## 11. 方案审阅结果

用户已接受上述整体默认项，并授权“审阅 → 写计划 → subagent-driven 连续实施”。只读 subagent 审阅未发现必须改变路线的阻碍，要求落实以下契约，已纳入[行为规范](行为规范.md)：

1. 回执与正文分开，result_revision 与当前 head 分开；旧成功不能复活旧正文。
2. 固定 pending 请求先持久化，uncertainSave 不能拿较晚输入改写原请求。
3. IndexedDB 清空正文后保留 fencing，阻止旧回调重建草稿。
4. 接管验证真实基线结构；升级后的兼容标记阻断旧协议 2 入口。
5. 真实 DDL 事务、外键设置顺序、约束/触发器完整性必须验证。
6. 已删除历史走专用只读路径，并提供网页可发现入口；活动写入仍拒绝删除对象。
7. 先检查当前 read 再重放本人回执；首次写入才检查 edit/冻结等，重放不产生副作用。
8. 主动退出完成本地写入后隐藏原账号内容、释放资格；本机无权限稿出口不授予服务器权限。

后续实现细节由既定路线与行为规范决定，重要新边界才集中提出，不再进行细粒度选择。
