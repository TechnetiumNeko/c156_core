# 修订与恢复

[索引](README.md)，[行为规范 H02–H04、W01–W03、W10、L09](行为规范.md)

正文修订追加 actor_id、source_kind、restored_from_revision_id，并与正文共同不可变。操作者是执行保存/恢复的账号，展示当前显示名；旧记录显示未知，不猜测作者。

`ContentService.list_document_revisions/read_document_revision/compare_document_revisions` 提供分页、详情及只读 unified diff。Vue DocumentHistory 与编辑 buffer 分离，查看和比较不替换未保存稿。工作区管理员可在 DeletedDocuments 发现已删除文档，仅查看和复制。

恢复将旧修订全文追加为当前正文：R1→R2→R3 后恢复 R1 得到 R4，parent=R3、restored_from=R1；目录、名称、metadata、权限不回退。当前正文相同仍先核验预期 revision，再返回无变化回执。首次恢复需要当前 read/edit、来源 history_read 和冻结允许。

界面恢复前提供保存当前稿、明确放弃、取消。存在 pending、在途请求或冲突先处理；保存后重新读取当前版本和比较，再允许确认。预览过期只报冲突，不推进基础自动重试。最终写操作统一经 DocumentSession.restore。

真实服务证据见 `tests/test_content_operations.py` 和 `tests/test_content_history.py`；协调器恢复守卫及结果确认见 `frontend/tests/document-session.test.ts`。Vue 接线通过类型检查和代码审阅验证，本轮没有浏览器截图或自动交互验证。
