# P0/P1 实施取舍

[目录](README.md)，[行为规范](行为规范.md)，[决策记录](决策记录.md)，[执行记录](执行记录.md)

以下按发生顺序记录实施期间自主处理的细节。既定路线来自 D27 的完整方案授权；这些记录不表示用户逐项确认，也不授权后续更换重要架构。

| 顺序 | 处理与理由 | 判断不成立时的代价或限制 |
| --- | --- | --- |
| 1 | 连续实施授权覆盖技能的任务间重复确认，按任务审阅推进 | 局部实现需要返工；不据此发布远端 |
| 2 | 清稿时即使仍由同一页面持有，也轮换持久化 fence，阻止旧回调复活 | 协调器须更新新 token |
| 3 | 用 dev-only fake-indexeddb 6.2.5 验证生产适配器关键事务行为 | 多一个测试依赖；不能证明原生故障、真实跨页锁或物理持久性 |
| 4 | 标准 Alembic 离线 SQL 用 sqlite3.complete_statement 在调用方连接执行；实测 SQLAlchemy Engine 包装会回滚调用方事务 | 若执行适配错误须返工迁移；用真实事务回滚证据约束 |
| 5 | 任务3仅补 session 测试 Bootstrap fixture 的必要 scope 字段 | 小范围测试数据调整，保留原行为断言 |
| 6 | 任务5补 .dockerignore 对 Alembic 配置和 migrations 的必要白名单 | 可撤回少量打包项，秘密和数据继续排除 |
| 7 | 后续鉴权/read 拒绝不清除先前结果不确定的 pending；本次拒绝不能证明此前没提交 | 保守保留 pending，可能需恢复权限后再确认 |
| 8 | 原账号无权限时，可确认后删除本机 pending，仍要求有效资格/fence并提供复制 | 删除会失去本机恢复和确认材料；已发服务器请求仍可能提交，界面必须明示 |
| 9 | 落盘失败默认阻止退出，已接受方案中的明确承认丢失退出路径照常实现 | 仅确认后可能丢失未落盘文字；已存记录保留，优先复制/重试 |
| 10 | 任务5修正明确采用手动合并基础后的本机 base，同已有真实协调器用例验证重开 | 小范围状态修正；不自动推进未解决的比较基础 |
| 11 | directory 测试 fixture 注入必需的真实 DocumentSession | 小范围 fixture 调整，保持行为断言，生产不加绕过入口 |
| 12 | 保留现有自动部署调用，不引入每次发布确认文件；脚本只能核实 Compose | 外部 CLI、旧 Web、后台进程需运维先停写；已有连接不受新版兼容阻断保护 |
| 13 | 通过只读 canEdit getter 向 UI 暴露既有协调器编辑守卫 | 若投影错误会显示错误的只读状态；生产守卫仍生效 |
| 14 | 成功离开/进入新上下文时清除旧 operationError，失败离开继续保留 | 过早清除可能隐藏错误；上下文完成和旧回调失效是前提 |

整分支审阅的 I1/I2 是确认的缺陷，均已修复并复审通过，见执行记录。项目快照、分支创建、实时协作、原位恢复删除、草稿库存/多副本、新 CLI 历史命令、回执 GC 和新稿后的数据库降级均按原范围延后。匿名操作者扩展和大规模容量指标未定义。真实镜像 smoke 与 test 发布已由 Actions 补充证据，见执行记录。原生浏览器故障、截图和 prod 发布仍未验证，不能由 Node 替身或源码审阅代替。
