# 虚拟文件系统

内容树由统一 SQLite 中的 entry 父子关系组织，与宿主机目录分离。CLI 及未来网页通过内容服务访问对象，普通宿主机文件不会通过目录扫描混入内容树。

初始化生成工作区根和四个兼容顶层目录：

| 目录 | 当前含义 |
| --- | --- |
| `main` | CLI 的访问根；显示为虚拟 `/` |
| `admin` | 兼容系统目录；尚无用户管理功能 |
| `resource` | 兼容资源目录；尚无上传或资源框架 |
| `bin` | 兼容目录；软删除不会自动搬入这里，也没有恢复界面 |

`initialize_database(Path)` 返回工作区根 scope；`ContentService.default_scope()` 返回 main scope。每次 API 操作都显式传入 `ContentScope(workspace_id, branch_id, root_id)`，路径与按 ID 请求均限制在其活动子树内。工作区、分支和访问根彼此不同；root_id 不是授权凭据。本阶段没有用户权限或分支切换。

路径支持绝对／相对形式、`.`、`..`、`~` 和连续 `/`；`~` 指访问根。逐段检查存在性与目录类型，文档后接 `..` 不会绕过类型检查，不能越过访问根。兄弟按 position 排序；`list_tree` 为先序，`max_depth=0` 仅返回起点，None 不限深度。

根及工作区默认顶层对象受保护，不能重命名、移动或删除。移动保持身份并更新后代显示路径；同名无变化操作先检查范围、保护和预期版本。非空目录默认不能删除；递归删除需确认子树 token，并在一次写事务内检测并发变化。软删除及正文历史保留，但恢复和回收接口尚未交付。

真实 `data/` 目录中的 7 个 `.folder` 和 1 篇文档仍是旧协议样本。通过显式 `migrate-legacy` 导入，不在 CLI 启动时扫描或改写。导入后 `/products/concretecream` 保留原 ID 和正文。运行库默认 `data/c156.sqlite`，不纳入 Git。管理命令见 [README](../README.md)。
