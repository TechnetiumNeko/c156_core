# 文件格式

运行内容统一存储在一个 SQLite 数据库中，默认路径是 `data/c156.sqlite`；快速演示使用相同协议的 `.c156/demo.sqlite`。数据库协议版本由 `PRAGMA user_version` 标识，当前为 **1**；正式运行库使用 WAL，每个连接启用外键并配置 5000ms busy timeout。不依赖 SQLite JSON 扩展。

| 数据 | 用途 |
| --- | --- |
| `workspaces`、`branches` | 工作区及内容分支；当前入口使用默认工作区的 main 分支 |
| `objects` | 稳定 ID、folder／document 类型和创建时间 |
| `entries` | 工作区与分支内的父目录、名称、兄弟 position、version、正文修订指针、扩展 metadata 和软删除状态 |
| `document_revisions` | 不可变正文、父修订与创建时间；UPDATE／DELETE 受触发器保护 |
| `legacy_imports` | 来源指纹、导入报告和完整导入记录；运行配置另行验证 |

账号和协作表属于后续协议扩展，目前尚未加入版本 1。设计上它们与内容表使用同一个数据库文件并不等于共用同一个 Repository：身份、授权和协作状态应各有独立的记录映射与服务边界。

路径从 entry 父子关系计算，不存为对象身份；对象移动后保留 ID，文档重命名与移动保留正文修订。兄弟名称及顺序受活动记录唯一约束保护。扩展 metadata 为严格 JSON：对象键必须是字符串，数值有限，拒绝结构字段、循环引用和不可序列化值；`None` 保存为 null。快照 metadata 深层只读，`get_metadata` 返回独立副本。

正文保存要求最初读取的 `revision_id`，即使正文无变化也先检测过期修订。结构操作要求预期 entry version；递归删除还要求 `prepare_delete` 返回的子树 token，以防覆盖确认后的并发修改。软删除保留身份及正文修订，不自动搬入 `bin`。

目前只交付 folder／document；程序执行、资源上传／回收、账号、权限、CRDT、作品级提交图、分支创建／切换及用户历史浏览／恢复均未实现。现有正文修订不是作品级 Git 提交，也不承担实时协作更新日志的职责。

## 后续身份与协作数据

后续账号系统可以增加用户、凭据摘要、会话、工作区成员关系、角色和 ACL 等表；Web 的 Cookie 或 Token 只保存会话引用，不直接成为内容表字段。授权服务将会话解析为 `Principal`，再结合 `ContentScope` 检查一次操作。

实时协作可以增加按工作区、分支和文档隔离的更新日志、协作快照、状态向量和压缩记录。协作更新用于自动同步和恢复，稳定正文检查点再写入内容版本或未来的阶段提交。这样可以分别保留“细粒度编辑历史”和“作者确认的成果版本”。

## 迁移来源

仓库 `data` 中保留旧单对象 SQLite 容器：目录在真实目录下以 `.folder` 保存元数据与子列表，文档以独立容器保存 `abstract_file`、metadata 和正文。它们仅作为离线迁移来源，由 `src.storage.legacy` 只读扫描；旧 `Document`／`Folder`／`SqlFile` 运行接口已经退出。

`python -m src.storage migrate-legacy --source data --database data/c156.sqlite` 保留原 ID、正文和 metadata，验证父子关系与排序，并记录缺失登记的修复和旧时间采用值。未知文件、损坏或矛盾容器、未恢复的 WAL／journal 会阻止导入。发布原子且不覆盖目标；发布后运行配置失败时保留完整目标，重跑原命令恢复。

运行库及其 sidecar 和临时文件不提交到代码 Git。详细约束见[设计方案](superpowers/specs/2026-09-30-single-sqlite-content-kernel-design.md)。
