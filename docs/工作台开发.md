# HTML／JS 工作台开发

工作台是供试手和架构演示使用的原生 HTML／JS 入口。目录、编辑与保存直接连接共用内容服务，保持模块简单，按需要接入新功能。

全项目的文件职责、内核阅读顺序和保存落盘链路见 [代码导览](代码导览.md)。本页聚焦页面事件与 API 的接线。

当前工作台只有 HTTP/JSON 入口，固定访问默认 `main` 范围；已接入登录、账号管理、成员／ACL／私密和文档冻结；尚无 WebSocket 或实时协作。Cookie 会话和 CSRF 由 HTTP 适配器处理，应用服务在同一事务内解析身份并执行授权；页面能力状态仅用于展示，不能替代后端检查。

## 页面与 API 接线

前端是直接加载的原生 JS 模块，修改后刷新页面即可。建议从 [app.js](../src/web/static/app.js) 底部的 `bindEvents()` 开始阅读：每个按钮都对应一个具名操作函数。启动从 `start()` 开始。

| 要修改的部分 | 文件 |
| --- | --- |
| 页面元素、按钮 ID、弹窗 | [index.html](../src/web/static/index.html) |
| 布局和样式（按区域分组） | [styles.css](../src/web/static/styles.css) |
| 按钮接线、打开／保存／新建／合并流程 | [app.js](../src/web/static/app.js) |
| 目录缓存、选择、展开和渲染 | [directory.js](../src/web/static/directory.js) |
| 登录、个人账号与站点账号管理 | [account.js](../src/web/static/account.js) |
| 成员／ACL／私密／冻结管理 | [access.js](../src/web/static/access.js) |
| HTTP 请求与错误提示 | [client.js](../src/web/static/client.js) |
| 草稿、保存基础、加载和保存状态 | [editor-state.js](../src/web/static/editor-state.js) |
| Markdown 渲染和 HTML 净化 | [preview.js](../src/web/static/preview.js) |
| JSON 字段到内容服务的适配 | [api.py](../src/web/api.py) |

新增普通 HTTP 操作按这条线接：`HTML 按钮 → bindEvents() → 操作函数 → Client 方法 → API.dispatch() → 应用服务`。当前共用 ContentService、IdentityService、AccountService、AccessService 与集中 AccessPolicy；前端不直接调用 Repository。操作函数拿到结果后，调用编辑状态或目录的方法，再更新展示。例如当前保存是 `saveDocument()` → `client.saveDocument()` → `state.saveSucceeded()` → `renderEditorStatus()`。

匿名 bootstrap 只返回 initialized 和预认证 nonce，不公开内容树。登录／激活／重置携带 X-C156-Nonce；其他写请求携带当前会话 X-C156-CSRF。会话使用 HttpOnly、SameSite=Strict、Path=/ Cookie，当前 loopback HTTP 可省略 Secure；实际 Host／Origin 端口必须匹配。X-C156-Instance 只用于演示入口复用服务，不授予身份或内容权限。

编辑状态只存数据，不访问 DOM 或网络；目录模块管理自己的缓存和 DOM。保存响应更新已保存的基础，用户继续输入的 `draft` 保留；刷新只更新目录与路径。草稿和请求结果绑定用户；换身份使旧响应失效。会话失效或权限丢失暂停保存，保留原草稿和基础 revision_id；同用户重登不替换基础，切换账号须先处理原草稿。配置冲突使用授权 version，正文冲突使用 revision_id，不能互换。

新增浏览器 JS 文件需加入 [http.py](../src/web/http.py) 的 `STATIC` 白名单，并重启服务。只改现有前端文件无需重启；修改 Python 适配器需要重启。依然无需构建、npm 开发服务器或前端框架。

实时协作接入时，前端只负责编辑器绑定、本地更新队列、断线重连、在线状态和展示；房间授权、更新合并、快照、压缩和持久化由后端 `CollaborationService` 负责。稳定检查点继续通过内容／版本服务保存，不能把每次输入直接当成 `document_revisions`。

## 运行与验证

启动和数据准备见 [README](../README.md)，使用方式见 [用户界面](用户界面.md)。

Python 测试使用临时数据库，前端状态测试使用 Node 标准库；不会操作演示库或原始样本：

```bash
python -m unittest discover -s tests -v
node --experimental-default-type=module --test tests/web/*.test.mjs
```

前端测试使用 Node 22。实际 HTML 净化检查额外使用 jsdom；没有安装时，仅该项明确显示为 skipped。需要执行它时，可把 jsdom 安装在仓库之外：

```bash
npm install --prefix /tmp/c156-web-checks --no-audit --no-fund jsdom@26.1.0
C156_JSDOM_PATH=/tmp/c156-web-checks/node_modules/jsdom \
  node --experimental-default-type=module --test tests/web/*.test.mjs
```

jsdom 仅用于验证，不是工作台的运行依赖。浏览器验证默认仅打开并截图，不自动点击、填表或执行交互流程。

本地 Marked／DOMPurify 资产、来源、版本与许可证见 [vendor 说明](../src/web/static/vendor/README.md)。不要修改压缩构建文件；升级时同步来源记录和 SHA-256。
