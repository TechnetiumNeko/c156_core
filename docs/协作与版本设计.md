# 协作与版本设计（后续阶段）

本文记录目标设计，相关能力尚未实现。当前工作台采用页面内存草稿和手动保存；正文修订是后续版本管理的数据基础。当前架构见 [架构分层](架构分层.md)，总体需求见 [需求整理](requirements.md)。本页同时约定身份、授权、实时协作和阶段版本之间的边界。

## 身份与授权边界

账号系统是跨入口的平台服务，不属于某个网页页面。身份认证回答“调用者是谁”，授权回答“调用者能对哪个工作区、分支或对象执行什么操作”。内容内核只接收已经解析出的调用者上下文和 `ContentScope`，不读取 Cookie，也不把访问根当作权限。

- 用户、凭据摘要、会话、成员关系、角色和 ACL 由独立的身份／授权服务管理。
- HTTP 和 WebSocket 负责把 Cookie、Token 或连接身份转换成 `Principal`；CLI 可以使用另一种凭据入口，但复用相同的授权服务。
- `ContentService` 在创建、读取、编辑、移动、删除、审核和发布前执行授权检查；所有入口共享这条规则。
- 初期可以把账号表与内容表放在同一个 SQLite 文件中，但身份 Repository、内容 Repository 和协作 Repository 分开，避免入口直接拼接 SQL。

## 实时协作边界

实时协作服务位于内容内核之上、WebSocket 适配器之下。它负责房间、成员授权、更新接收、同步、幂等、快照和压缩；它不负责浏览器 DOM，也不让浏览器直接写数据库。

```text
编辑器本地更新
      ↓
WebSocket 适配器：握手、心跳、消息 framing、断线重连
      ↓
CollaborationService：房间、授权、同步、更新日志、快照
      ↓
协作领域规则：CRDT／OT 更新、版本向量、合并与幂等
      ↓
稳定检查点 → ContentService → document_revisions／阶段提交
```

CRDT 或 OT 的纯更新模型可以放在领域内核中；房间生命周期、在线状态、消息广播和连接限流属于应用服务或传输适配器。前端需要深度绑定编辑器和同步协议，但协作服务仍应能被 CLI、后台任务或测试以非 Web 方式调用。

## 共享草稿与阶段版本

项目用于朋友之间共同创作架空小说，章节、人物档案和世界观设定需要一起维护。协作与版本管理按以下方式分工：短时间尺度的日常编辑参考实时协作文档，默认同步向前推进；较大时间尺度的创作成果参考 Git 的提交、分支和合并。

| 层次 | 行为 | 用途 |
| --- | --- | --- |
| 共享草稿 | 同一分支内的作者实时共同编辑，自动同步和保存 | 日常写作，修改标点或几个字无需手动提交 |
| 协作更新日志 | 保存细粒度更新、状态向量和协作快照 | 断线恢复、会话恢复和自动收敛 |
| 草稿恢复记录 | 自动保存可恢复状态，编辑历史可按时间或会话合并展示 | 恢复误删内容和未完成的工作 |
| 阶段提交 | 作者主动确认一组修改，填写提交说明，形成不可变快照 | 记录“完成第三章”“统一人物背景”等有意义的成果 |
| 里程碑与发布 | 标记或发布一个已确认的提交 | 固定“第一卷初稿”“连载版”等阅读和分享版本 |

是否创建阶段提交由作者对成果的确认决定，同时考虑时间尺度和修改的语义。自动保存和细小的同步事件无需各自生成正式提交；主要版本时间线展示阶段成果，草稿恢复历史提供更细的回溯。协作更新日志与稳定正文修订分开存储，阶段提交再引用已经确认的正文、目录和媒体版本。

### 分支与合并的范围

- 分支覆盖整个作品／工作区，一次提交可以同时包含章节、人物设定等多篇文档。
- 每个分支拥有自己的共享草稿；实时同步以“工作区＋分支＋文档”为范围，不同分支独立编辑。
- 从阶段提交创建分支，探索不同改稿方案；分支内继续使用实时协作。
- 提交需要捕获服务器已确认的一致状态，记录文档修订、目录结构及引用的媒体版本。后续编辑继续进入草稿，已创建的提交保持不变。
- 合并请求比较共同祖先、目标分支和来源分支的版本，支持人工处理冲突并由有审核权的人确认。文本能够自动合并时，仍需审核剧情和设定的一致性。
- 合并前需要处理目标分支的未提交草稿，并协调正在编辑的客户端，避免覆盖现有工作。
- 恢复旧成果通过创建新提交保留操作经过；发布与草稿编辑分别管理，继续写作不改变已发布的版本。

### 参考现有协作库

共享文档功能优先参考和复用成熟的实时协作库及编辑器集成，例如 [Yjs](https://docs.yjs.dev/)。可以利用已有库处理并发编辑、同步和协作状态，编辑器、传输方式及服务端接入方案在实现时选定。

项目自身负责工作区与分支的隔离、身份和权限检查、协作状态的持久化，以及阶段快照、提交关系、审核和合并。实时编辑的自动同步与跨分支的成果合并分别处理；协作库的自动收敛不能代替剧情和设定审核。WebSocket 只是传输适配器，不能替代授权服务、协作服务或内容内核。
