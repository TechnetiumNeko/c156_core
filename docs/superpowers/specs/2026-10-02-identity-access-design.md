# 用户与权限系统设计

状态：设计稿，待整体审阅；尚未批准实施。2026-10-02。

本文承接现有内容内核和本地工作台。本会话的交付目标是用户与权限系统；实时协作、阶段版本和发布只保留必要边界，不在本阶段实现。

## 1. 已确认的方向与待确认项

用户已确认：

- 管理员邀请或创建账号，用户通过站内用户名与密码登录；不开放自行注册。
- 父目录不可读时整个子树不可读；子文档的允许规则不能绕过祖先的阅读限制。
- 增加 argon2-cffi 运行依赖，使用 Argon2id 密码摘要与验证。
- 应用用例统一持有事务，跨子系统操作共享连接与提交边界。
- 各应用用例强制执行授权，授权模块集中计算策略。
- 后续实时协作采用共享文档算法，不用全文 save_document 的修订比较实现实时合并；算法和库尚未选定。
- 作品级阶段版本独立建模。
- 本阶段面向新库开发，不建设既有数据库升级流程。

本文其余标为“建议”的产品规则需要随完整设计一起审阅，不能视为已获实施授权。最值得审阅的是站点/工作区管理权限分离、跨目录移动限制，以及冻结解除规则。

## 2. 交付范围

建议交付以下完整链路：

- 首个管理员的显式本机初始化；后续管理员创建待激活账号。
- 用户设置初始密码、登录、退出、修改密码；管理员停用账号和发起密码重置。
- 工作区成员管理，预设角色，目录默认权限与对象例外。
- Web 与 CLI 共用身份和授权服务；所有现有内容读写入口执行授权。
- 文档冻结及解除冻结；必要的管理审计记录。
- 现有工作台内的登录、账号状态、成员与权限管理入口，沿用现有页面组织和样式。

第一版使用当前默认工作区，不顺带实现多工作区创建与切换。数据关系保留 workspace_id，成员关系不能成为全站角色。

审核权、发布权可以作为独立权限值建模和配置；只有将来对应业务交付后才有可执行操作。本阶段不提供假的审核、发布或历史恢复入口。

不实现邮件发送、开放注册、第三方登录、MFA、实时协作、作品分支、数据库升级、自动删除旧库或公网部署。原始旧容器样本保持原样。发现旧运行库时给出使用新路径初始化的指引，不静默覆盖。

## 3. 子系统与数据所有权

| 模块 | 拥有的数据和规则 | 不承担的职责 |
| --- | --- | --- |
| Identity | 用户、密码摘要、账号状态、激活与重置凭据、会话 | 内容树遍历及作品权限计算 |
| Access | 工作区成员、角色、对象权限规则、冻结状态 | 登录验证、正文写入 |
| Content | 对象、目录结构、metadata、正文检查点 | Cookie、密码处理、成员管理 |
| Application | 调用者解析、用例顺序、事务、授权执行、审计协调 | HTTP 解析、SQL |
| Storage | 各模块的 Repository、同库事务、约束 | 决定调用者可以做什么 |
| Web / CLI | 凭据传入、请求解析、交互与错误展示 | 自行查询权限表、接受客户端指定的管理员身份 |

延续当前横向目录结构，按实际职责增加 identity、access 和用例内部模块，不为了目录整齐先做全仓重构。

Principal 是本次操作中解析出的可信身份。ContentScope 仍只界定工作区、分支与访问根。外部输入的 user_id、role、root_id 均不能直接成为授权结论。

账号、会话和成员关系是工作区/站点管理状态；对象 ACL 与冻结状态属于独立授权数据，不写进普通 metadata，也不自动随未来作品回滚恢复。

## 4. 统一事务与可组合的内容操作

现有 ContentService 每个方法自行开启事务，需要调整为两个责任：公开应用用例负责事务；事务内的内容操作复用当前连接，不再开启嵌套事务。

概念调用链：

```text
HTTP / CLI
  → 公开应用用例（凭据、scope、参数）
    → 开启短读事务或 BEGIN IMMEDIATE
      → 在该事务中验证会话、账号和成员状态
      → 从同一连接构造 Identity / Access / Content Repository
      → 执行授权判断
      → 执行内容操作及必要审计写入
    → 成功提交后返回纯数据结果
```

组合操作在同一应用工作单元中使用事务内能力。Repository 与事务内服务不 commit、不重新连接；事务失败时所有本次变更回滚。持有事务的对象不得逃逸到入口或页面会话中。

入口只调用公开用例，不能继续保留“未传身份则视为全权”的旧调用方式。初始化和离线导入使用独立、显式的管理路径，不提供可由 HTTP 参数开启的系统身份。

读取也在同一快照中解析身份和权限。授权撤销与内容写入按 SQLite 写事务顺序生效：先提交的撤销阻止后续写入；已先取得写事务的合法操作可完成，不承诺撤销已提交内容。

密码摘要计算与密码验证在写事务外进行。登录先读取凭据快照，计算完成后在短写事务中重新核对账号状态和 credential_version，再签发会话，避免停用/重置期间使用旧校验结果登录。

## 5. 账号生命周期建议

### 5.1 创建和激活

- 使用不可变用户 ID。登录名与显示名分开；登录名为 3–32 位 ASCII 字母、数字、下划线或短横线，以字母开头，大小写折叠成小写并唯一；显示名为 1–80 字符，支持中文，不作为权限标识。第一版不更改登录名。
- 管理员创建待激活用户，系统生成限时、一次性的激活凭据，用户自行设置密码。
- 初期由管理员人工转交激活码，不接入邮件。原始凭据仅在生成时返回一次，不写日志。
- 激活凭据绑定用户和用途，有效期 48 小时，库中保存摘要；激活、凭据消费和账号启用原子完成。重发使旧凭据失效。激活完成后正常登录，不在激活接口隐式签发会话。
- 首个站点管理员由显式本机管理命令创建，密码交互输入；首个管理员同时被显式授予默认工作区所有者身份。未初始化时网页不开放“抢注第一个管理员”。

### 5.2 修改密码、重置与停用

- 用户修改密码需要当前会话及旧密码；成功后撤销旧会话，重新登录。
- 管理员发起重置时生成有效期 1 小时、绑定 reset 用途的单次凭据，账号进入 reset_required 状态，阻止旧密码继续登录并撤销现有会话；用户设置新密码后恢复 active 状态。停用账号不能通过旧激活/重置凭据重新启用；停用同时撤销未消费凭据。
- 账号停用保留用户 ID 和历史归属，撤销会话和未消费凭据；重新启用进入 reset_required 状态并生成新重置凭据，由用户设置密码，不复活旧会话。
- 第一版不物理删除用户，不允许停用最后一个有效站点管理员。工作区最后一个有效所有者也必须先完成转交，避免无法管理的工作区。

### 5.3 密码与会话

采用已确认的 argon2-cffi 密码接口，封装于独立 PasswordHasher 适配器，领域模型不依赖该库。建议固定 Argon2id 参数为 memory_cost=19456 KiB、time_cost=2、parallelism=1、salt_len=16、hash_len=32，保存库生成的完整编码摘要。密码允许 15–128 个 Unicode 字符，不截断、不去空格、不做大小写或 Unicode 规范化；允许粘贴与密码管理器。不自行实现密码算法。详见文末一手资料。依赖版本在实施计划中固定，运行环境缺失依赖时明确报错，不退化到其他算法。

会话建议使用 32 字节安全随机数编码成的不透明令牌，数据库保存 SHA-256 摘要、用户 ID、签发时的 credential_version、过期与撤销状态，不把权限快照编码进令牌。激活和重置凭据同样使用 32 字节随机数及摘要。账号状态、成员关系和权限在每次操作中重新读取。会话绝对有效期为 24 小时，第一版不滑动续期，避免每次读取都变成写事务。

浏览器通过 HttpOnly、SameSite Cookie 携带会话；Cookie 与 CSRF 处理留在 Web。当前仅 loopback HTTP 的运行方式需要明确开发 Cookie 配置，不能因此将未来 HTTPS 的 Secure 配置省略。CLI 使用同一身份服务，令牌初期只保留在当前进程内存，密码不出现在命令行参数中。

登录失败使用统一提示；不存在、停用、待激活及密码错误不返回可区分账号状态的错误。对不存在账号也执行等成本的虚拟密码校验。

建议在昂贵摘要计算前通过数据库限流：按规范登录名每 15 分钟最多 10 次登录尝试；激活/重置按凭据摘要每 15 分钟最多 10 次尝试；同时 HTTP 按直连源地址每 15 分钟最多 60 次认证请求，CLI 进程入口采用固定 local 来源桶而非用户可指定地址。修改密码按用户 ID 每 15 分钟最多 10 次尝试。计数在独立短事务中先提交，校验失败不会回滚计数；窗口结束可重试，不永久锁账号。每次最多清理 100 条过期桶，单表最多 10000 个活动桶，达到上限拒绝新桶而不逐出有效限制。成功登录不清空窗口计数。限制命中返回统一的 rate_limited 错误及重试时间。

账号管理、成员/权限管理均要求当前有效会话；授权变化无需强制用户重新登录才生效。

## 6. 角色与动作建议

角色是便于管理的权限组合，服务仍按具体动作判断。

| 工作区角色 | 默认能力 |
| --- | --- |
| reader | 阅读 |
| editor | 阅读、编辑正文及普通 metadata、新建、重命名、删除；跨目录移动受第 7.2 节额外限制 |
| admin | 管理内容、成员和权限；不能移除或替换所有者 |
| owner | 工作区管理、所有权转交；保证至少保留一名有效所有者 |

审核与发布不因 editor 角色自动获得，应独立授予。游客和登录但非成员的用户默认无内容访问权；工作区可以显式设置阅读范围 members、authenticated 或 everyone，默认 members，作为全树阅读基线，再通过目录/对象规则收紧。该设置只影响阅读，不授予其他动作。所有内容写操作要求有效工作区成员身份。带有失效凭据的请求返回身份失效，不能悄悄降级成游客继续访问。

站点管理员负责账号管理；不因站点角色自动获得所有作品的阅读权限。初始站点管理员可读默认工作区，是因为另有明确的 owner 成员关系。

第一版权限规则管理集中授予工作区 admin/owner，普通作者不会因创建文档自动获得修改 ACL 的能力。授权管理与普通编辑分开，避免编辑者给自己提权。

工作区 admin/owner 对本工作区具有管理性阅读和内容动作权限，不受普通内容 ACL 阻断，以便纠正错误规则；冻结仍要求按第 7.3 节显式处理。角色变更中只有 owner 能授予/撤销 admin 或转交 owner；admin 仅管理 reader/editor 成员。站点管理员没有隐式内容绕过，但可通过账号恢复流程恢复合法所有者账号，操作有审计。

## 7. 目录继承与例外

用户已确认：祖先的不可读状态封闭整个子树。将“动作规则继承”和“阅读路径检查”分开计算，既保留文件例外，也保证不能穿过不可读目录。

示例一：工作区默认 reader 可读；“内部设定”目录对 reader 禁止阅读；其中“人物简介”对 reader 单独允许阅读。该 reader 仍不能读取简介，知道 ID 也无效。

示例二：“内部设定”可读但默认禁止编辑；其中“人物简介”对某个有效成员单独允许编辑。在阅读路径全部可达且未被冻结的前提下，该成员可以编辑简介。

动作规则按以下确定顺序计算：

1. 验证账号状态、工作区/分支/访问根以及对象的完整活动祖先链。
2. 对从分支根到目标的每个节点分别计算 read；任一节点不可读便拒绝目标读取及所有内容写入。ContentScope.root_id 不截断授权祖先链。
3. 对需要的其他动作，从目标节点向上寻找最近的适用规则。每一层主体优先级依次为指定用户、调用者当前工作区角色、authenticated、everyone；通用主体仅允许配置 read。找到本层适用规则后立即使用其 allow/deny，不与其他来源取并集。
4. 没有任何对象规则时回退到工作区角色默认能力；非成员仅可能通过工作区阅读范围获得 read。其余默认拒绝。
5. 对修改再执行成员资格、冻结、对象保护、版本等独立约束。

同一节点、主体、动作最多一条规则。没有条目表示继承，删除条目恢复继承；显式 deny 与继承不同。工作区管理员可查看决定来源，普通内容结果不泄露完整 ACL。

节点动作集合为 read、edit、create、rename、move、delete、review、publish。create 仅适用于文件夹；review/publish 仅保存和解释权限，不产生本阶段不存在的业务操作。成员和权限管理由工作区角色控制，不作为可由对象 ACL 任意委派的动作。

授权继承必须沿真实分支祖先查到工作区根，不能因为调用者换了较深的 ContentScope.root_id 就跳过祖先策略；范围限制和权限计算分别执行。

### 7.1 结果的可见性

当前 NodeSnapshot 含完整 path、parent_id、position 和 metadata。由于已确认所有祖先必须可读，成功读取可继续提供访问根内的正常路径，无需增加隐藏祖先的特殊文档视图。

目录列表只返回可读孩子，树遍历不进入不可读目录；补全复用经过过滤的列表。对外列表不提供未过滤的总数，position 不暴露隐藏孩子造成的真实序号间隙，按可见序列生成展示位置。访问根快照不返回范围外 parent_id。内部 Repository 记录保留真实结构用于事务操作。

文档自身正文和普通 metadata 由作者负责其中主动写入的内容，系统只裁剪自身附带的结构及管理信息。未经许可不可读的对象采用统一的不存在结果；可读但不可执行某动作时返回权限不足。错误 details 不能包含隐藏对象或范围外祖先。直接读取、路径解析和未来搜索执行相同规则。

### 7.2 修改目录结构

- 新建检查目标文件夹的新建权；新对象默认继承目标目录规则。
- 重命名检查目标对象的重命名权。
- 同父改名按 rename 处理。跨目录移动检查源对象移动权和目标文件夹新建权，并要求工作区 admin/owner；因移动可改变全部后代的继承权限，不在第一版实现复杂的普通作者委派移动。对象显式 ACL 跟随对象，继承部分即时取新祖先规则；移动和规则效果在同一事务中生效。
- 删除检查目标；递归删除逐个核对活动后代删除权，任一失败便整体不执行，不返回隐藏对象信息。
- 已有 expected_version、正文修订和子树 token 继续检测数据冲突；权限变化每次重新判断，token 不充当权限凭据。

### 7.3 冻结

冻结是独立的写入约束，不能被普通 ACL allow 绕过。第一版仅冻结文档。具有当前 read/edit 权限的文档创建者或工作区管理员可以冻结；冻结者仍可在自身正常权限范围内操作，其他人不能编辑、重命名、移动或删除该文档。

冻结者或工作区 admin/owner 可显式解除冻结，操作写审计。管理员不会静默绕过他人的冻结，先解除再修改。冻结不额外授予阅读或编辑权，被移除成员或撤销编辑权的冻结者仍不能编辑。移动/递归删除目录也逐个检查活动后代文档冻结，不允许通过修改祖先绕过。

## 8. 存储落点

继续使用同一个 SQLite 文件，分别设置 Repository。数据集与关键约束如下，具体 SQL 交给实施计划：

- users：稳定身份、唯一规范登录名、显示名、账号状态、站点管理标识、账号/凭据代次和时间。状态为 invited、active、reset_required、disabled；停用不是物理删除。凭据代次在发起重置、成功改密及停用/重新启用时更新；令牌和会话均绑定签发代次。
- password_credentials：以用户 ID 为主键，保存密码摘要和对应凭据版本。权威凭据代次由 users 保存，只有 active 账号且摘要版本与当前代次一致时才可签发会话；无凭据的 invited 用户不能登录。
- account_tokens：用途 activate/reset、用户、唯一令牌摘要、凭据代次、过期/消费/撤销状态；按用户/用途/代次检查单次消费。
- sessions：唯一令牌摘要、用户、凭据版本、CSRF 随机值、签发/过期/撤销状态；CSRF 值不是认证令牌。按用户索引以支持全会话撤销。
- workspace_memberships：工作区和用户联合唯一，角色、active/removed 状态及管理版本；移除后旧用户 ACL 不再授予该用户成员资格。
- workspace_access_settings：每工作区一行，默认阅读范围 members/authenticated/everyone、授权版本；由 admin/owner 修改。
- access_rules：workspace_id、branch_id、object_id、主体类型 user/role/authenticated/everyone、主体键、动作、allow/deny。完整规则键唯一，复合外键保证对象属于所声明工作区和分支；指定 user 主体必须是该工作区成员。移除成员时删除其专属规则，重新加入不会意外恢复旧例外。
- content_ownership：以工作区/对象为唯一键，保存初始创建者，可空值表示初始化/旧数据导入；归属不因改名、移动或账号停用改变，也不自动授予权限。第一版不提供更改创建者接口。
- content_locks：以工作区/分支/对象为唯一键，保存冻结者和时间；只引用文档。解除时删除活动锁并保留审计，移除成员不悄悄解除其冻结，交由管理员处理。
- audit_events：账号、成员、权限和冻结等管理变更的操作者、目标、时间及必要前后状态；创建者和管理操作者对普通读者不随内容接口自动公开，为后续匿名展示保留边界。
- auth_throttles：认证入口使用的限流桶、窗口及次数，清理不影响账号状态。

审计不记录密码、原始会话/激活凭据或正文。管理变更和对应审计原子提交，浏览器收到成功即表示二者已持久化。审计属于站点管理数据，不随未来作品内容版本回滚。

成员和授权管理接口携带 expected_version；在应用写事务中比较版本后再更新，防止两个管理员相互覆盖。每次 ACL、成员、工作区阅读范围或冻结修改递增相应管理版本，正文修订不承担此职责。第一次创建使用服务器返回的当前工作区授权版本。

本阶段直接定义新的初始化 schema 并更改 SCHEMA_VERSION，旧运行库明确拒绝。既不保留协议号却暗中改变表结构，也不实现自动升级。离线旧容器导入构建完整新 schema，用户与授权处于未引导状态，需要显式创建首管理员。

## 9. 入口与兼容性

- Web：匿名可取登录所需的最小启动信息；登录后返回当前用户及可用工作区入口。客户端传入身份字段不能改变调用者。
- HTTP 会话令牌只在 Cookie 传输，应用服务不处理 Cookie 字符串；CLI 将会话令牌传入同一个服务入口。Web 不接受 user_id 作为调用者，也不在 URL 传递会话、密码或激活凭据。
- Web 写操作保持 JSON 和自定义请求头校验：登录/激活前使用启动随机 nonce、严格的 Host/Origin 检查且不开放 CORS；登录后使用独立的会话 CSRF 值。登录建立新会话并更新 CSRF；退出撤销服务端会话并清除 Cookie。会话 CSRF 值可由有效会话启动接口读取，不能充当认证凭据。
- 本地 Cookie 使用 c156_session、HttpOnly、SameSite=Strict、Path=/、不设置 Domain，生命周期不超过服务端 24 小时期限；仅当前 loopback HTTP 模式允许不设置 Secure。服务绑定继续为 127.0.0.1，接受的 Host/Origin 端口必须等于实际监听端口。未来非 loopback 部署需单独设计 HTTPS 配置，不由本阶段开放。
- 工作台：登录与账号流程复用现有页面；权限不足的动作不展示或禁用，但服务端仍重新检查。登录过期或撤权导致保存失败时保留未保存草稿。
- CLI：启动时认证；目录、补全、读取与写入遵循相同权限。当前目录失去访问权时回到可访问位置；不存在可访问根时显示无可用内容，不能死循环重试默认根。
- 演示：新示例库显式建立身份初始状态，通过正常登录访问；不建立免授权的演示后门。已有演示库不会被自动清空。
- 管理：显式初始化、首管理员引导、旧数据离线导入与运行入口分开。运行服务不会自动初始化账号或修复 schema。

入口契约按以下用例组织，具体路由名称在计划中固定，不与 CLI 命令文本耦合：

| 调用方 | 应用用例 | 身份与权限 |
| --- | --- | --- |
| 匿名或尚未登录 | 取得登录启动信息、提交激活/重置凭据、登录 | nonce/来源校验；凭据接口单次消费及限流 |
| 当前用户 | 查询当前会话、退出、修改密码和显示名 | 有效会话；修改密码验证旧密码 |
| 站点管理员 | 创建/列出账号、重发激活码、发起重置、停用/启用、管理站点管理员 | 有效站点管理员；最后管理员/所有者约束 |
| 工作区管理员 | 列出成员、精确登录名添加已有账号、移除或修改普通成员、配置 ACL 与阅读范围 | admin/owner；不得通过成员查询遍历无关站点用户 |
| 工作区所有者 | 任免工作区管理员、转交所有权 | owner；保留有效所有者 |
| 内容调用者 | 既有读取/创建/保存/metadata/改名/移动/删除，以及冻结/解冻 | 有效身份或明确访客 read；统一范围和逐动作授权 |

Web 本阶段对外增加账号/成员/权限/冻结管理所需入口；现有仅通过 Python 使用的移动、删除等能力完成服务授权，但不顺带建设完整文件管理 UI。页面返回可执行动作供展示，服务端每次操作重新核对，客户端展示状态不是权限凭据。

用户接口中不暴露会话摘要、密码摘要、凭据代次或完整内部用户记录。401 表示缺少或失效身份，403 表示可见对象上缺少动作权限，404 表示对象不存在或不可见，409 表示版本冲突，429 表示限流。未知异常继续统一映射为内部错误。

## 10. 验收重点

复用现有临时库夹具，在实际服务和 SQLite 上验证关键行为，避免每层重复同一套场景。

- 未登录、过期、撤销、停用用户无法执行需要身份的操作；失效会话不被当作有效成员。
- 激活/重置凭据单次消费；重发、过期与并发消费符合契约。
- 用户不能指定他人身份、提升自己的角色、通过 metadata 修改 ACL。
- 同一授权规则约束 HTTP、CLI 与服务操作；列表、路径和按 ID 访问没有旁路。
- 继承、例外、移动和递归删除用具体父子树验证；不可见信息不出现在结果及错误中。
- 授权读取和写入使用同一事务；跨模块中途失败时内容、成员/权限及审计一并回滚。
- 密码验证与账号重置/停用竞争时，不签发基于过时凭据的有效会话。
- 已有内容冲突和失败草稿保留行为继续成立。
- 运行相关既有 Python/前端检查；新增永久测试仅补上述真实行为缺口。页面最多打开截图，不自动点击或填表。
