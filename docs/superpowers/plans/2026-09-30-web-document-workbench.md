# HTML／JS 文档工作台实施记录

状态：已完成。记录 2026-09-30 至 2026-10-01 的工作台交付与可读性整理；当前使用方式见 [README](../../../README.md)，开发接线见 [工作台开发](../../工作台开发.md)。

**目标：** 浏览器与 CLI 共用内容内核，提供便于试手和演示的目录、Markdown 编辑／预览与保存入口。

**设计契约：** [工作台设计](../specs/2026-09-30-web-document-workbench-design.md)。

## 交付内容

- [x] 标准库 HTTP 适配器：固定 main scope、显式 JSON 序列化、领域错误映射与静态资产白名单，内容操作只调用 ContentService。
- [x] 浏览器工作台：目录懒加载、新建、源码／预览／并排、手动保存和快捷键、未保存正文保护。
- [x] 并发编辑状态：原始换行的无变化保存、过期加载隔离、保存期间输入保留、冲突保留基础修订、显式手动合并。
- [x] 本地预览依赖：固定版本 Marked／DOMPurify、净化策略、来源／SHA-256／许可证记录，无运行时 CDN 请求。
- [x] 快速演示入口：`run_demo.py`、`start_demo.sh`，位于旧样本树外的独立示例库首次准备、后续内容保留、重复启动复用服务与端口冲突处理。
- [x] 可读性整理：具名操作函数、集中的 `bindEvents()`、独立目录模块、明确的 Client 方法、格式化 HTML／CSS／JS 和关键状态注释。

## 验证与审查

Python 验证包含真实临时数据库上的 HTTP 读写、独立服务可见性、修订冲突、scope 与请求来源边界、静态路径限制、缺库和协议校验。前端验证涵盖 CRLF、保存中输入、加载竞态、冲突、手动合并、离开保护、客户端 JSON 契约和实际 vendor 净化。

独立工作台审查发现并修复了两个正文保护问题：保存中撤回到初始文本时仍提醒关闭；开始合并后独立保留的旧草稿在关闭和切换时继续受保护。已有相关状态验证覆盖这两种情况。

启动脚本和目录模块另以一次性检查验证，不扩展永久测试套件。桌面及窄屏页面只打开并截图，没有浏览器自动点击或填表。

Python 验证包含既有内核检查、3 项 HTTP 集成检查及运行库／旧样本隔离的针对性回归检查；前端有 10 项检查，其中实际 DOM 净化需可选 jsdom。最新结果以 PR 的验证记录为准；原始样本与 vendor 文件散列不变。

## 保持的边界

- Web 与 CLI 通过相同的 ContentService 执行事务、范围和版本检查。
- 常规入口不自动初始化数据库；显式演示入口只准备独立示例库。
- 仅绑定 loopback，页面草稿只存在于当前内存中，不提供自动保存或实时协作。
- 本地开发机的桌面快捷方式、运行库、缓存和审查日志不进入代码 Git。
- 登录／权限、作品分支、提交图、历史恢复、媒体上传与公网部署继续留在后续阶段。
