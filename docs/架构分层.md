# 项目分层与入口

C156 的目标是供用户共同创作和阅读内容的网站。抽象文件系统负责组织内容；CLI 是当前便于开发和验证的终端入口，网页是计划中的用户入口。CLI 的 `ls`、`cat`、`edit` 等命令只是终端交互方式，不定义网页 API，也不是内容对象自身的接口。

## 目标关系

```text
CLI（当前入口） ──┐
                 ├──→ 内容服务 ──→ 抽象文件系统 ──→ 存储实现
网页（计划入口）──┘          └──→ 修订与版本管理（计划）
```

- **内容内核**：管理文件对象的稳定 ID、类型、目录关系、文档正文及后续的引用等内容关系。修订与版本管理将记录这些对象的历史与分叉；它们尚未实现，具体存储方案也未确定。
- **内容服务**：面向入口提供列目录、读取、创建、保存等操作，并在有用户系统后统一执行身份与权限检查。它是计划中的共享边界，当前代码尚未形成独立的服务层。
- **入口**：CLI 和网页分别处理各自的输入与展示，调用相同的内容服务。网页不解析命令字符串，不调用 `CLI.execute()`，也不启动终端编辑器。
- **存储实现**：当前原型把虚拟目录映射到 `data` 中的真实目录，并使用 SQLite 文件保存对象数据。这个映射不决定上层入口如何交互。

例如，CLI 的 `ls` 与网页中的目录浏览都需要“列出目录内容”；CLI 的 `cat` 与网页中的文档阅读都需要“读取文档”。CLI 的 `edit` 包含终端交互，网页编辑则应分别调用读取和保存操作。两种入口共享内容操作，而不共享终端命令。

## 当前实现范围

目前已有抽象文件记录、目录和文档的 SQLite 存储，以及直接调用这些存储对象的 CLI 和测试用终端编辑器。网页入口、共享内容服务、用户认证与授权、修订与版本管理均未实现。因此上图描述的是目标边界，不表示现有 CLI 已经通过内容服务访问存储。
