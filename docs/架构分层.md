# 项目分层与入口

C156 的目标是供用户共同创作和阅读内容的网站。抽象文件系统负责组织内容；CLI 是当前便于开发和验证的终端入口，网页是计划中的用户入口。CLI 的 `ls`、`cat`、`edit` 等命令只是终端交互方式，不定义网页 API，也不是内容对象自身的接口。

## 当前分层

```text
CLI／终端编辑器 → ContentService → Repository → Database／SQLite
未来网页入口    → ContentService
纯 core 模型、路径和领域错误不依赖存储或入口
```

- **入口**：CLI 管理 cwd、补全、命令解析与展示。编辑器只接收文档 ID、标题和正文并返回编辑结果，不持有持久化对象。网页尚未实现，将使用结构化内容操作。
- **ContentService**：执行范围、类型、保护、版本与业务规则，组装纯数据快照；每次操作拥有一个短读事务或 `BEGIN IMMEDIATE` 写事务。服务不写 SQL，不依赖入口。
- **Repository**：执行参数化 SQL，按工作区和分支过滤；共享服务提供的连接，不自行 begin／commit／rollback、重连、初始化 schema 或调用服务。
- **Database**：负责连接、事务、外键、5000ms busy timeout 和运行配置验证。运行打开拒绝缺失、未知版本及非 WAL 数据库，不隐式修改。
- **管理入口**：显式 init 或 migrate-legacy；初始化与迁移发布后完成 WAL 配置。旧 bootstrap 只转发显式 init。旧单容器读取集中于离线迁移模块。

入口统一通过服务读取、创建和保存；CLI 不扫描宿主机内容目录，编辑器只可读取自身静态帮助。初始化返回工作区根 scope，而 CLI 的默认 scope 以 main 文件夹为虚拟 `/`。所有按 ID 操作同样检查活动访问根，root_id 不代表用户权限。

正文以不可变修订保存，revision_id 检测正文冲突；entry.version 检测结构与 metadata 冲突，子树 token 检测递归删除确认后的并发变化。服务不自动重试领域冲突。终端编辑、确认和等待均处于事务外；失败 buffer 保留原基础修订，不能自动绑定最新版本覆盖他人内容。

## 共享草稿与阶段版本

项目用于朋友之间共同创作架空小说，章节、人物档案和世界观设定需要一起维护。协作与版本管理按以下方式分工：短时间尺度的日常编辑参考实时协作文档，默认同步向前推进；较大时间尺度的创作成果参考 Git 的提交、分支和合并。

| 层次 | 行为 | 用途 |
| --- | --- | --- |
| 共享草稿 | 同一分支内的作者实时共同编辑，自动同步和保存 | 日常写作，修改标点或几个字无需手动提交 |
| 草稿恢复记录 | 自动保存可恢复状态，编辑历史可按时间或会话合并展示 | 恢复误删内容和未完成的工作 |
| 阶段提交 | 作者主动确认一组修改，填写提交说明，形成不可变快照 | 记录“完成第三章”“统一人物背景”等有意义的成果 |
| 里程碑与发布 | 标记或发布一个已确认的提交 | 固定“第一卷初稿”“连载版”等阅读和分享版本 |

是否创建阶段提交由作者对成果的确认决定，同时考虑时间尺度和修改的语义。自动保存和细小的同步事件无需各自生成正式提交；主要版本时间线展示阶段成果，草稿恢复历史提供更细的回溯。同步日志的合并存储与正文历史的保留要求需要分别设计。

### 分支与合并的范围

- 分支覆盖整个作品／工作区，一次提交可以同时包含章节、人物设定等多篇文档。
- 每个分支拥有自己的共享草稿；实时同步以“工作区＋分支＋文档”为范围，不同分支独立编辑。
- 从阶段提交创建分支，探索不同改稿方案；分支内继续使用实时协作。
- 提交需要捕获服务器已确认的一致状态，记录文档修订、目录结构及引用的媒体版本。后续编辑继续进入草稿，已创建的提交保持不变。
- 合并请求比较共同祖先、目标分支和来源分支的版本，支持人工处理冲突并由有审核权的人确认。文本能够自动合并时，仍需审核剧情和设定的一致性。
- 合并前需要处理目标分支的未提交草稿，并协调正在编辑的客户端，避免覆盖现有工作。
- 恢复旧成果通过创建新提交保留操作经过；发布与草稿编辑分别管理，继续写作不改变已发布的版本。

### 参考现有协作库

共享文档功能优先参考和复用成熟的实时协作库及编辑器集成，例如 [Yjs](https://docs.yjs.dev/)。可以利用已有库处理并发编辑、同步和协作状态，编辑器、传输方式及服务端接入方案在实现时选定。

项目自身负责工作区与分支的隔离、身份和权限检查、协作状态的持久化，以及阶段快照、提交关系、审核和合并。实时编辑的自动同步与跨分支的成果合并分别处理；协作库的自动收敛不能代替剧情和设定审核。

## 当前实现范围

单 SQLite 协议 1、共用 ContentService、CLI／编辑器接入、离线迁移、正文修订、严格 metadata、移动／重命名与软删除均已实现。运行库和 sidecar 不纳入代码 Git；旧 data 样本保留。CLI 继续保留原命令集合，新增内核操作通过 Python API 验证。

上文共享草稿、作品级版本流程为后续设计：网页、用户认证／权限、CRDT、分支创建／切换、提交图、媒体框架及用户历史浏览／正文或删除恢复尚未交付。bin 为兼容顶层目录，不是自动回收站。最终集成审阅待完成。
